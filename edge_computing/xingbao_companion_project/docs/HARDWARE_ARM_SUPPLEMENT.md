# 星宝硬件设计机械臂补充材料

> 用途：补充到当前硬件设计汇报和关系图中。当前图里已经包含 SC171 V3、触控屏、麦克风、摄像头、声卡/扬声器、云端服务、电源分配和纸箱桌体，但缺少机械臂相关内容。本材料专门说明机械臂应该如何接入整套硬件系统、与其他模块形成什么关系，以及右侧说明文字应该如何撰写。

## 1. 机械臂在整机中的定位

机械臂不是独立完成学习任务的核心计算单元，而是星宝的“肢体表达与空间引导模块”。它承担的是把系统的语音、屏幕、游戏反馈进一步转化为儿童能直接感知的实体动作，让星宝从一个会说话、会显示内容的桌面系统，变成一个有身体表达、有陪伴感、有空间指向能力的交互伙伴。

在比赛汇报中，机械臂建议表述为：

> 机械臂作为星宝的实体动作反馈模块，接收 SC171 V3 核心平台输出的高层动作指令，通过点头、摇头、挥手、左右指向和小幅庆祝等动作，与语音播报、屏幕表情、触控游戏形成多模态反馈闭环，增强儿童的沉浸感、陪伴感和任务引导效果。

机械臂在系统里的关键词是：

- 实体陪伴：让星宝不只是屏幕角色，而是有身体动作的陪伴对象。
- 空间引导：通过 `point_left`、`point_right` 等动作提示儿童关注桌面或屏幕的指定区域。
- 情绪反馈：通过 `nod`、`shake_head`、`wave_hand`、`small_dance` 等动作表达鼓励、纠错、欢迎和庆祝。
- 安全受控：主控平台只输出高层动作名，具体电机控制、动作幅度和安全限位由机械臂控制模块内部完成。

## 2. 关系图中需要新增的硬件模块

当前图中建议新增两个节点，而不是只加一个“机械臂”框。这样评委能看清楚：SC171 V3 不直接驱动舵机，而是通过动作控制模块完成安全隔离和动作执行。

### 2.1 机械臂控制模块

建议图中名称：

```text
机械臂控制模块
高层动作接收 · 动作组映射 · 安全限位
```

作用说明：

- 接收 SC171 V3 发出的高层动作指令，例如 `wave_hand`、`nod`、`shake_head`、`point_left`、`point_right`、`small_dance`、`bow`、`stay_still`。
- 将高层动作指令映射为机械臂内部动作组。
- 管理动作节奏、复位、限位和异常保护。
- 屏蔽底层电机控制细节，避免上层系统直接控制舵机角度、PWM 或原始硬件命令。

在图中的位置建议：

- 放在 SC171 V3 核心计算平台的右下方，靠近声卡/扬声器和纸箱桌体。
- 它应该既连接 SC171 V3，又连接机械臂执行机构，还接入总电源/电源分配。

### 2.2 桌面机械臂执行机构

建议图中名称：

```text
桌面机械臂
点头 · 摇头 · 挥手 · 指向 · 庆祝
```

作用说明：

- 安装在纸箱桌体或桌面结构上，作为星宝的实体动作输出部件。
- 执行欢迎、鼓励、纠错、方向提示、庆祝等动作。
- 与屏幕角色、语音播报、灯效共同构成儿童可感知的多模态反馈。

在图中的位置建议：

- 放在“纸箱桌体与实体教具区”的右上方或右侧。
- 使用结构连接线连到“纸箱桌体与实体教具区”，表示机械臂由桌体承载和固定。
- 使用动作输出线指向“儿童与实体教具区”，表示它对儿童产生可见、可理解的动作反馈。

## 3. 关系图中需要新增的连接线

下面这几条线是机械臂补充图最关键的部分。制图时建议用不同线型或颜色区分“控制”“供电”“结构固定”“交互反馈”。

| 序号 | 起点 | 终点 | 线条含义 | 建议标注 | 说明 |
|---|---|---|---|---|---|
| 1 | SC171 V3 核心计算平台 | 机械臂控制模块 | 控制数据 | 高层动作指令 | 主控只发送动作名，不直接控制底层电机 |
| 2 | 机械臂控制模块 | 桌面机械臂执行机构 | 内部动作控制 | 动作组/安全限位 | 控制模块把动作名转换成机械臂可执行动作 |
| 3 | 总电源/电源分配 | 机械臂控制模块 | 供电 | 独立低压供电 | 机械臂建议使用独立供电分支，避免影响主控和屏幕 |
| 4 | 总电源/电源分配 | 桌面机械臂执行机构 | 执行机构供电 | 动力供电 | 如实际由控制模块转供电，可画成“总电源 → 控制模块 → 机械臂” |

| 6 | 桌面机械臂执行机构 | 儿童/桌面交互区 | 物理反馈 | 指向/挥手/点头 | 表示机械臂向儿童提供空间提示和情绪反馈 |
| 7 | 摄像头/触控屏/麦克风 | SC171 V3 核心计算平台 | 输入触发 | 语音/触控/视觉触发 | 这些输入触发 SC171 判断是否需要机械臂动作 |

```text
动作反馈给儿童
指向桌面区域/游戏目标
```

## 4. 机械臂与现有硬件的交叉关系

机械臂不是一条孤立的支线，它会和电源、语音、触控屏、摄像头、纸箱桌体形成交叉关系。关系图里最好把这些交叉讲清楚。

### 4.1 与 SC171 V3 的控制关系

SC171 V3 是全局交互调度中心。儿童的语音、触控、游戏状态、视觉感知结果都会先进入 SC171 V3，由它判断当前应该输出什么反馈。

当需要实体动作时，SC171 V3 向机械臂控制模块发送高层动作指令：

```text
SC171 V3 → 机械臂控制模块 → 桌面机械臂执行机构
```

推荐图中标注：

```text
高层动作指令
wave_hand / nod / shake_head / point_left / point_right
```

注意不要在汇报图里写：

```text
舵机角度
PWM
GPIO
原始串口命令
```

因为比赛答辩时这样容易被追问安全性和软件边界。更好的表述是：上层只发动作语义，底层控制由机械臂模块内部封装。

### 4.2 与电源分配的关系

机械臂属于动作执行硬件，瞬时电流和稳定性要求通常高于普通传感器。关系图中应把机械臂画成电源分配的重要分支。

推荐图中标注：

```text
总电源/电源分配 → 机械臂控制模块
总电源/电源分配 → 桌面机械臂执行机构
```

或在更简洁的图中画成：

```text
总电源/电源分配 → 机械臂控制模块 → 桌面机械臂
```

说明文字可写：

> 机械臂采用独立供电分支，由电源分配模块提供稳定低压电源，避免机械动作产生的电流波动影响 SC171 V3、触控屏、麦克风和音频输出。机械臂动作执行时由控制模块统一管理动作节奏和复位策略，保证系统运行稳定。

如果实际硬件已经确定了电压、电流和供电接口，再在图中补具体数值；如果还没确定，不建议提前写死。

### 4.3 与触控屏的关系

触控屏负责显示角色、内容、游戏和提示，机械臂负责把屏幕提示转化成空间动作。

典型关系：

```text
儿童点击屏幕 → SC171 V3 判断游戏状态 → 屏幕显示反馈 + 机械臂动作反馈
```

例子：

- 儿童答对：屏幕显示微笑/星星奖励，扬声器播放鼓励语音，机械臂执行 `nod`。
- 儿童答错：屏幕显示温和提示，扬声器播放“再试一次”，机械臂执行 `shake_head` 或保持 `stay_still`。
- 需要选择左侧目标：屏幕高亮左侧区域，机械臂执行 `point_left`。
- 需要选择右侧目标：屏幕高亮右侧区域，机械臂执行 `point_right`。

这条关系能体现“触控不是孤立输入，机械臂也不是孤立输出”，两者一起服务桌面游戏引导。

### 4.4 与语音交互的关系

语音模块提供自然交互，机械臂提供同步肢体回应。

典型关系：

```text
USB 麦克风 → SC171 V3/云端 ASR+LLM → TTS 回复 + 屏幕表情 + 机械臂动作
```

例子：

- 儿童说“星宝你好”：星宝语音回应，屏幕微笑，机械臂 `wave_hand`。
- 儿童说“我做对了吗”：星宝判断当前游戏状态，答对时 `nod`，需要重试时 `shake_head`。
- 儿童说“给我一点提示”：星宝根据任务目标执行 `point_left` 或 `point_right`，并同步语音提示。

这条关系可以在右侧说明中写成：

> 机械臂动作与 TTS 语音和屏幕表情同步触发，形成“说得出、看得见、动起来”的陪伴式反馈。

### 4.5 与摄像头/视觉感知的关系

如果项目中摄像头作为扩展能力接入，可把机械臂与视觉感知组成安全和引导闭环。

典型关系：

```text
USB 摄像头 → SC171 V3 视觉判断 → 机械臂动作/语音提醒/屏幕提示
```

可用于：

- 判断儿童是否离屏幕太近：语音提醒 + 屏幕护眼提示 + 机械臂 `shake_head` 或 `stay_still`。
- 判断桌面教具所在区域：机械臂 `point_left` / `point_right` 指向目标区域。
- 判断儿童是否完成摆放：机械臂 `nod`，屏幕显示奖励动画。

如果摄像头当前还没有实机接入，图中摄像头和视觉闭环可以使用虚线；机械臂仍然可以作为触控和语音触发的实体反馈模块。

### 4.6 与纸箱桌体的关系

用户已经搭建纸箱桌体，并把它变成桌面形式。机械臂补充后，纸箱桌体不只是外壳，而是承担机械臂安装、固定、承载和线缆整理的结构角色。

建议图中标注：

```text
纸箱桌体与实体教具区 → 桌面机械臂
固定 · 承载 · 走线 · 安全距离
```

说明文字可写：

> 纸箱桌体作为低成本快速原型结构，承担触控屏摆放、实体教具分区、机械臂固定、线缆隐藏和交互空间划分等作用，使硬件系统从“散装模块”转化为可演示的桌面产品形态。

## 5. 机械臂相关功能闭环

### 5.1 欢迎唤醒闭环

```text
儿童靠近/语音唤醒/点击开始
→ 麦克风或触控屏输入
→ SC171 V3 判断进入交互状态
→ 扬声器播放欢迎语
→ 屏幕显示微笑表情
→ 机械臂挥手 wave_hand
→ 儿童感知到星宝“醒来并回应”
```

汇报表达：

> 通过语音、屏幕和机械臂的同步反馈，星宝在启动和唤醒阶段形成拟人化欢迎效果，降低儿童进入学习任务的心理距离。

### 5.2 答题鼓励闭环

```text
儿童完成触控选择或桌面操作
→ SC171 V3 判断答案/游戏状态
→ 答对：TTS 鼓励 + 屏幕奖励 + 机械臂点头 nod
→ 答错：TTS 温和提示 + 屏幕引导 + 机械臂摇头 shake_head
→ 儿童根据反馈继续探索
```

汇报表达：

> 机械臂把抽象的“对/错”判断转化为儿童容易理解的点头、摇头动作，与语音和画面共同构成正向反馈闭环。

### 5.3 空间指引闭环

```text
游戏需要儿童关注左侧/右侧区域
→ SC171 V3 输出区域引导
→ 屏幕对应区域高亮
→ 机械臂执行 point_left 或 point_right
→ 儿童把注意力转向目标区域
→ 完成触控或实体教具操作
```

汇报表达：

> 在桌面游戏中，机械臂承担空间指向作用，可以把屏幕中的任务目标和真实桌面区域对应起来，提升儿童对任务步骤的理解。

### 5.4 护眼与安全提醒闭环

```text
摄像头或交互状态发现儿童距离过近/姿势不合适
→ SC171 V3 触发健康提醒
→ 屏幕显示护眼提示
→ 扬声器播放温和提醒
→ 机械臂保持 stay_still 或轻微 shake_head
→ 儿童调整距离和姿势
```

汇报表达：

> 机械臂在健康提醒场景中不进行大幅动作，而是配合语音和屏幕完成温和提醒，避免干扰儿童操作或造成安全风险。

### 5.5 通关庆祝闭环

```text
儿童完成一轮游戏/连续答对
→ SC171 V3 汇总游戏进度
→ 屏幕播放奖励动画
→ 扬声器播放鼓励语音
→ 机械臂执行 small_dance 或 wave_hand
→ 儿童获得成就感
```

汇报表达：

> 机械臂在任务完成时提供小幅庆祝动作，让学习结果具备仪式感，增强儿童持续参与的积极性。

## 6. 机械臂动作白名单与场景映射

机械臂动作建议只使用高层白名单，避免在汇报材料中出现底层控制。

| 高层动作 | 中文含义 | 推荐使用场景 | 与其他模块同步 |
|---|---|---|---|
| `stay_still` | 保持不动 | 默认状态、听孩子说话、思考、护眼提醒时避免动作干扰 | 屏幕 thinking / 蓝色呼吸灯 |
| `wave_hand` | 挥手 | 开场欢迎、唤醒成功、退出告别、重新开始游戏 | TTS 欢迎语、屏幕 smile |
| `nod` | 点头 | 答对、确认、完成一步、儿童完成回合 | TTS 鼓励语、屏幕奖励动画 |
| `shake_head` | 摇头 | 答错、温和纠错、距离过近提醒 | TTS “再试一次”、屏幕温和提示 |
| `point_left` | 指向左侧 | 引导儿童关注左侧选项、左侧桌面区域或左侧教具 | 屏幕左侧高亮、语音提示“看左边” |
| `point_right` | 指向右侧 | 引导儿童关注右侧选项、右侧桌面区域或右侧教具 | 屏幕右侧高亮、语音提示“看右边” |
| `small_dance` | 小幅庆祝 | 通关、连续答对、完成游戏 | 屏幕庆祝动画、彩虹灯效、TTS 表扬 |
| `bow` | 鞠躬 | 开场礼貌欢迎、结束感谢、展示礼仪互动 | TTS 问候语、屏幕 smile |

如果比赛演示现场机械臂只实现了其中一部分动作，图中可以写成：

```text
支持动作：挥手、点头、摇头、左右指向、小幅庆祝
```

不要把尚未实现的动作说成已经完整支持。未实现动作可以描述为“预留动作扩展”。

## 9. 更新后的总关系描述

加入机械臂后，整机硬件关系可以概括为：

```text
输入层：
USB 麦克风、触控屏、摄像头、实体教具/桌面操作

核心层：
SC171 V3 核心计算平台，负责语音理解、游戏调度、多模态融合、网络通信和反馈决策

输出层：
22.5 英寸触控屏、声卡/功放/扬声器、桌面机械臂、灯效或其他桌面反馈

结构层：
纸箱桌体固定屏幕、教具和机械臂，完成桌面形态验证

支撑层：
总电源/电源分配为主控、屏幕、音频、摄像头和机械臂提供稳定供电；Wi-Fi/LAN 连接云端 ASR、LLM、TTS 服务
```

加入机械臂后的核心闭环是：

```text
儿童输入
→ 麦克风/触控屏/摄像头/实体教具
→ SC171 V3 多模态判断
→ 语音回复 + 屏幕表情 + 机械臂动作
→ 儿童获得反馈并继续操作
```

这个闭环比原图多了一个很重要的实体动作出口，使系统从“语音 + 屏幕交互”升级为“语音 + 触控 + 视觉 + 实体动作”的多模态陪伴桌。

## 10. 适合放进比赛汇报的精简版文案

如果只需要放到 PPT 或讲稿中，可以使用下面这版：

> 本项目在原有 SC171 V3 核心平台、触控屏、麦克风、摄像头和音频输出基础上，补充桌面机械臂作为实体动作反馈模块。机械臂不直接参与核心计算，而是接收 SC171 V3 输出的高层动作指令，由独立控制模块完成动作组映射、安全限位和复位管理。它可以通过挥手、点头、摇头、左右指向和小幅庆祝等动作，与 TTS 语音、屏幕表情、触控游戏和纸箱桌体实体教具区形成联动闭环。儿童在答题、选择、请求提示和完成任务时，不仅能听到反馈、看到反馈，还能看到星宝做出相应动作，从而增强陪伴感、沉浸感和学习引导效果。
