# 游戏语音、状态同步与体验优化结果

日期：2026-07-23

## 已完成

### 1. 中央语音生命周期

- `speech_request` 支持 `wait_for_finish`。
- 中央在播放函数真正返回后才回复 `finished`。
- 播放异常回复 `failed`，并携带安全错误类型。
- 回执会原样带回 `utterance_id`、`speech_role`、`page_state`、`game_id`、`question_id`。
- 旧客户端不传 `wait_for_finish` 时仍保持快速 `queued` 响应，兼容原协议。

### 2. 游戏端语音状态

- 新增独立 `src/speech_state.py`，不继续把语音状态堆在主页面类里。
- 欢迎、难度提示、题目、手动读题、提示、反馈分别带明确 `speech_role`。
- 每次语音有唯一 `utterance_id`；旧题的迟到回执不能覆盖新题。
- 页面切换、题目切换和手动读题会打断当前旧语音，并清除尚未播放的同通道旧提示。
- 等待超时的排队任务会真正取消，之后不会再补播。
- UI 请求顺序带“会话 epoch + 单调序号”；即使多条 TCP 连接乱序到达或 UI 进程重启，旧会话/旧序号也不能反向覆盖新题。
- 可替换语音的网络合成彼此独立；新题不需要等待旧题的缓存未命中合成超时。
- `activate_display()` 重新进入游戏时会再次播放欢迎语。
- “读题”调用当前题目生成器，题目文字与屏幕目标来自同一份状态。

### 3. 页面与语音同步

- 答题反馈至少展示 1.15 秒。
- 匹配语音播放完成后才进入下一题。
- 中央失败也视为终态，允许安全继续。
- 无回执时最多等待 8 秒，避免游戏永久卡死。
- `get_game_state()` 新增 `ui_state`、`page_state`、`question_id`、`question_prompt` 和 `speech`。
- 反馈页保存“刚刚回答的题目”上下文；答对后即使内部已生成下一题，接口和读题按钮也不会提前暴露下一题。

### 4. 语音缓存

- 新增 `config/game_speech_cache.json`，包含 64 条固定欢迎、导航、题目和反馈短语。
- 固定短语使用可读文件名，并按音色 ID 隔离目录。
- 英语、算术和组合反馈等动态文本按“音色 ID + 规范化文本”生成 SHA-256 稳定缓存文件名。
- 缓存小于等于 1000 字节会标记为损坏，不会当成可播放文件。
- 运行时和后台预热都先写每任务唯一临时文件，完成后原子替换正式缓存；下载一半的 WAV 不会暴露给播放器。
- `--prepare-demo-tts-cache` 会补齐缺失文件。
- `--check-game-tts-cache` 只检查、不联网。
- 板卡正式启动脚本会先开放中央语音服务，再在后台逐条预热；首次启动不会被 64 条网络合成阻塞。
- 后台预热每条只短暂占用一次 TTS 锁，实时游戏语音可在当前条目完成后继续。

当前本机缓存检查为 `64 missing`。这是因为缓存目录不打进发布包，且板卡 SSH 当前不可用；不能把本机状态写成“板卡已预热”。本次代码已经具备首次板卡启动自动补齐机制。

### 5. 其他回归问题

- 恢复本地天气/节日知识的快速答复。
- 恢复需要直接处理的成长引导，避免无意义调用大模型。
- 修正监听事件顺序。
- 修正实时 TTS 的开场白重复、混入正式回复和预热互锁。
- 打开游戏后继续生成自然回应，不再错误结束整个会话。
- 未启用 `--board-ui` 时不再向内部 API 传空客户端参数。
- 颜色积木语音兼容旧编码输入。

## 用户体验改动

- 游戏主页去掉 SC171V3、AIoT Console 等开发者术语。
- “低/中/高难度”改为“轻松玩/认真想/勇敢挑战”。
- “演示本模式”改为“先看看怎么玩”。
- “退出”改为“返回桌面”。
- “锁定目标”改为“请找到”。
- 右上角新增语音播放、完成、失败、未连接状态。
- 答题卡小提示扩大并改成“点一下”，整卡仍为触控区域。
- 反馈期间选项区变暗，减少继续点击的误导。
- 小结页去除重复长句，后续动作名称更直白。

完整截图与逐步审查见 `docs/UX_AUDIT_AND_OPTIMIZATION_20260723.md`。
