# 当前画面物品理解设计

## 目标

当孩子询问“这是什么”“你看我拿的是什么”“你看到了什么”等需要观察当前画面的内容时，星宝由 Qwen 自主调用摄像头工具，读取 `http://127.0.0.1:4445/?action=stream` 的一帧图像，并由同一个多模态 Qwen 依据图片回答。普通聊天不读取、不上传摄像头画面。

## 范围与边界

- 使用现有 `qwen3.7-plus` 与百炼兼容 Chat Completions 接口。
- 图片只保存在内存：从流中取得最新有效帧后压缩为 JPEG data URI；不创建图片文件、不写入对话历史或日志。
- 使用现有摄像头 HTTP 流，不改动运行中的本地 YOLO、脸部、情绪、手势或击掌进程。
- 仅在模型调用 `inspect_current_camera` 时访问摄像头；工具判定本身仅有文字和已有对话上下文。
- 每次工具调用只允许一帧，取帧总等待时间上限为 2 秒。

## 两阶段调用流程

1. 每轮普通问答先向 Qwen 发送文本、系统提示、近期对话、现有实时工具和新工具定义 `inspect_current_camera`。
2. 系统提示要求：只有回答确实依赖星宝**此刻**看见的物体、动作或画面时才调用此工具；不因为泛泛聊天、故事、回忆或无法从画面回答的问题调用它。
3. 如果没有该工具调用，继续现有文本流式回复逻辑，不产生额外摄像头读取或网络图像请求。
4. 调用该工具时，应用立即发送 `realtime_query_started` 兼容事件，工具名为 `inspect_current_camera`，底部字幕为 `正在识别中`；不播报额外等待语音。
5. 工具打开独立的 OpenCV HTTP-stream 捕获，读取到一张非空 BGR 帧后释放捕获；缩放最长边至 1024 像素、JPEG 质量 80，并形成内存 data URI。
6. 将第一阶段 assistant tool call、tool result 和一条包含原问题与 data URI 图片的用户消息发送给 Qwen。第二阶段以当前流式输出、TTS、字幕和场景标记处理链生成自然语言回答。

## 工具协议

工具定义：

```json
{
  "type": "function",
  "function": {
    "name": "inspect_current_camera",
    "description": "仅当回答必须观察星宝此刻摄像头画面时调用，例如用户问手中、面前或镜头中的物体是什么。",
    "parameters": {"type": "object", "properties": {}}
  }
}
```

工具结果不含图片字节，只表示快照是否成功。图片只附在紧随其后的第二阶段图文用户消息中，格式使用兼容接口的 `image_url` data URI。

## 失败与不确定结果

以下情况均使用固定、不会猜测的回复：

> 我现在看不清，能把它靠近一点、拿稳一点吗？

- 摄像头流无法连接、超时、没有解码出有效帧；
- JPEG 编码或图文请求失败；
- Qwen 明确表示画面模糊、被遮挡或无法确定物体。

模型指令也要求不得把不确定的物体当作确定答案说出。

## UI 与语音

- 工具开始时复用 `realtime_query_started` 的 UI 处理，传递 `subtitle="正在识别中"` 与空 `voice_prompt`。
- 该字幕属于对话优先级，不得被外部通知覆盖。
- 快照/图像理解完成后，最终回复继续使用原有流式字幕和 TTS；不新增独立语音。

## 测试与可观测性

- 工具选择：无工具调用时不能读取摄像头；调用 `inspect_current_camera` 时只读取一次。
- 图文请求：验证图片以 data URI 出现在第二阶段消息中，且第一阶段不含图片。
- 失败：取帧失败与模型不确定均返回固定澄清语，不调用普通猜测回复。
- UI 事件：工具调用发送“正在识别中”，且不排队等待语音。
- 日志只记录工具名、耗时、成功/失败原因、图像尺寸；绝不记录 base64 或写入图像文件。
