# 星宝动作与表情交付说明

本文档用于交给负责机械臂动作和星宝表情设计的同学。目标是把星宝当前允许输出的动作、表情、光效整理清楚，并让游戏/硬件侧评估哪些能实现、哪些需要替换、哪些需要新增。

## 一句话原则

星宝侧只输出高层动作名和表情名，不输出舵机角度、PWM、GPIO、串口原始命令。

游戏和硬件侧负责把这些高层动作映射成具体动画、表情帧、灯效或机械动作。

## 当前动作白名单

当前项目中的机械臂/动作白名单来自 `config/action_schema.json` 的 `arm_actions`。

| 动作名 | 建议含义 | 典型使用场景 | 需要同学确认 |
| --- | --- | --- | --- |
| `stay_still` | 保持不动 | 默认安全状态、星宝听孩子说话、思考时不做机械动作 | 是否所有状态都能安全保持 |
| `wave_hand` | 挥手 | 开场欢迎、唤醒成功、游戏开始 | 机械臂能否自然挥手，是否有安全幅度限制 |
| `nod` | 点头 | 答对、确认、鼓励、孩子完成一步 | 能否实现点头或等价动作 |
| `shake_head` | 摇头 | 答错、温和纠错、提醒重试 | 能否实现摇头或等价动作 |
| `point_left` | 指向左侧 | 引导孩子看左侧区域、左侧选项提示 | 机械臂是否能安全指左 |
| `point_right` | 指向右侧 | 引导孩子看右侧区域、右侧选项提示 | 机械臂是否能安全指右 |
| `small_dance` | 小幅庆祝动作 | 通关、连续答对、完成游戏 | 是否能安全实现，是否会过度晃动 |
| `bow` | 鞠躬 | 开场欢迎、唤醒成功、礼貌回应 | 请硬件组确认安全幅度和复位方式 |

如果某个动作机械臂不能实现，请不要直接删除，而是返回替代建议，例如：

```text
point_left 不能实现，建议改为屏幕左侧高亮 + 星宝眼睛看左。
small_dance 风险较高，建议改为屏幕庆祝动画 + warm_breath 光效。
```

## 当前表情白名单

当前项目中的星宝表情白名单来自 `config/action_schema.json` 的 `screen_expressions`。

| 表情名 | 建议含义 | 典型使用场景 | 需要同学确认 |
| --- | --- | --- | --- |
| `neutral` | 默认中性 | 待机、无特殊状态 | 是否有默认待机表情 |
| `smile` | 微笑 | 欢迎、答对、鼓励、普通回答 | 是否已有常用微笑帧 |
| `thinking` | 思考 | 星宝正在判断、等待游戏返回、孩子操作中 | 是否有思考动画 |
| `curious` | 好奇 | 提问、引导探索、发现新内容 | 是否需要眼睛/头部小动作 |
| `sad` | 难过/温和失落 | 答错但不能打击孩子、安慰场景 | 是否适合儿童场景，避免过度负面 |
| `surprised` | 惊喜 | 孩子答得很好、发现新结果 | 是否有惊喜帧 |
| `sleepy` | 休息/安静等待 | 退出聊天、休息提醒、长时间无操作 | 是否有休息动画 |

## 当前光效白名单

当前项目中的光效白名单来自 `config/action_schema.json` 的 `led_modes`。

| 光效名 | 建议含义 | 典型使用场景 |
| --- | --- | --- |
| `off` | 关闭 | 默认或无光效 |
| `blue_breath` | 蓝色呼吸 | 待机、聆听、安静状态 |
| `warm_breath` | 暖色呼吸 | 鼓励、陪伴、温和提示 |
| `yellow_blink` | 黄色闪烁 | 提醒、等待孩子确认 |
| `rainbow` | 彩虹 | 通关、庆祝、连续答对 |
| `red_flash` | 红色闪烁 | 错误、危险提醒、需要慎用 |

## 星宝侧输出格式

星宝侧输出给游戏/硬件层的动作应该是结构化的高层 proposal，例如：

```json
{
  "screen_expression": "smile",
  "arm_action": "nod",
  "led_mode": "warm_breath"
}
```

注意：

- 所有字段都必须在白名单内。
- 非白名单字段会被 sanitizer 降级。
- 不允许出现 `servo angle 120`、`舵机角度120度`、`PWM=...` 这类原始硬件控制。
- 如果 `arm_action` 不是 `stay_still`，当前 sanitizer 会优先保留机械动作，避免同时叠加不确定光效。

## 游戏场景推荐映射

下面是第一版建议映射，后续需要同学根据实际表情/机械臂能力修订。

| 游戏事件 | screen_expression | arm_action | led_mode | 说明 |
| --- | --- | --- | --- | --- |
| 游戏开始 | `smile` | `wave_hand` | `warm_breath` | 星宝欢迎孩子开始 |
| 等待孩子操作 | `thinking` | `stay_still` | `blue_breath` | 不干扰孩子操作 |
| 答对 | `smile` | `nod` | `warm_breath` | 鼓励确认 |
| 答错 | `sad` | `shake_head` | `yellow_blink` | 温和纠错，不批评 |
| 请求提示 | `curious` | `point_left` / `point_right` / `stay_still` | `yellow_blink` | 根据目标位置决定 |
| 通关/完成 | `surprised` 或 `smile` | `small_dance` | `rainbow` | 庆祝，但注意动作安全 |
| 暂停/休息 | `sleepy` | `stay_still` | `blue_breath` | 引导休息 |
| 退出游戏 | `smile` | `wave_hand` | `warm_breath` | 温和告别 |

## 给同学的嘱托

请重点思考这些问题：

1. 哪些机械臂动作实际做不出来？
2. 哪些动作虽然能做，但不适合儿童近距离桌面场景？
3. 哪些动作更适合用屏幕表情或光效替代？
4. `point_left` / `point_right` 是否真的需要机械臂指向，还是用屏幕区域高亮更安全？
5. `small_dance` 是否会造成晃动、噪音或安全风险？
6. 表情资源是否足够覆盖游戏中的鼓励、思考、纠错、休息和庆祝？
7. 游戏事件和动作/表情之间是否需要更细的映射？

最终目标不是“动作越多越好”，而是每个动作都安全、清晰、孩子能理解，并且不会干扰触控游戏。
