# TTS 队列与语音打断机制

本文档说明当前星宝语音播放的执行规则。

## 1. TTS 播放队列

普通 TTS 统一通过 `multimodal.audio_io.speak()` 进入播放队列。

队列规则：

1. 同一时间只播放一段语音。
2. 多个模块同时请求 TTS 时，按进入队列的先后顺序执行。
3. 每条任务按顺序完成“合成音频 -> 播放音频”。
4. 队列会等待当前任务结束后，再处理下一条任务。

这可以避免以下问题：

- 两段 TTS 同时播放，声音重叠。
- 多个线程同时写入同一个缓存音频文件。
- 小游戏提示、主对话回复、状态查询回复抢占声卡。

## 2. 播放期 VAD 打断

在星宝播放 TTS 时，语音主流程会启动 `_TTSBargeInGuard`。

它同时支持两种打断来源：

| 来源 | 说明 |
| --- | --- |
| 唤醒词 | 播放时听到“星宝星宝”，立即打断 |
| VAD 人声检测 | 播放时检测到孩子开始说话，立即打断 |

打断后会设置同一个 `interrupt_event`。底层播放函数会持续检查该事件，当前语音会停止播放。

事件记录：

```json
{
  "type": "tts_interrupted",
  "reason": "speech",
  "vad": {
    "rms": 900.0,
    "start_threshold": 180.0
  }
}
```

如果是唤醒词打断：

```json
{
  "type": "tts_interrupted",
  "reason": "wake_word",
  "keyword": "星宝星宝"
}
```

## 3. 当前接入范围

已经接入播放期打断的场景：

- 只唤醒后的固定回复
- 结束会话固定回复
- 游戏状态查询回复
- 打开游戏前后的自然回复
- 成长引导固定回复
- 普通聊天流式回复
- 普通聊天非流式回复

## 4. 板卡调试注意

播放期 VAD 会用麦克风实时监听孩子声音。上板后如果出现“星宝自己播出的声音把自己打断”，优先调整：

1. 提高 `vad_manual_threshold`
2. 提高播放期 VAD 的 `threshold_multiplier`
3. 增大播放期 VAD 的 `start_hold_ms`
4. 调低扬声器音量或改变麦克风与扬声器位置

当前实现保留高层逻辑，不涉及底层硬件控制。
