同学你好，这个压缩包是“星宝和触控游戏协同”的交付资料。

我们现在要解决的是：颜色、图形、记忆这三个触控游戏，怎样和星宝语音交互、星宝表情、灯效、机械臂动作协同起来。

请你先看：

1. GAME_XINGBAO_HANDOFF_PACKAGE.md
   这是总目录，说明每份文件是干什么的，以及建议阅读顺序。

2. GAME_XINGBAO_COLLAB_RULES.md
   这是我们双方共同遵守的规则。核心原则是：
   游戏负责规则、状态、分数、关卡和触控结果；
   星宝负责听懂孩子说话、归类意图、组织语音反馈。

3. GAME_XINGBAO_API_SPEC.md
   这是接口规范。第一版你这边只需要提供一个固定命令处理函数：
   Python 可以是 handle_command(command: dict) -> dict
   JavaScript 可以是 handleCommand(command)

4. GAME_INTENTS_V0.md
   这是第一版意图表。星宝会把孩子的话整理成固定 intent，比如 get_hint、get_rule、get_score。
   你需要确认颜色、图形、记忆三个游戏分别支持哪些 intent，以及每个 intent 应该返回什么。

5. GAME_STATE_TEMPLATE.md
   这是三个游戏状态模板。请你根据真实游戏逻辑补充每个游戏的状态字段、事件和返回内容。

6. ACTION_EXPRESSION_HANDOFF.md
   这是当前星宝允许输出的机械臂高层动作、屏幕表情和灯效白名单。

7. ACTION_EXPRESSION_FEASIBILITY_TEMPLATE.md
   这是需要你回填的模板。请你判断哪些动作、表情、灯效能实现，哪些不能实现，哪些有安全风险，以及替代方案。

8. MESSAGE_TO_GAME_DEV.md
   这是任务说明的详细版，也可以作为你开发时的对照说明。

请你最后尽量返回两类东西：

第一类：游戏接口相关
- 三个游戏分别支持哪些 intent。
- 每个 intent 会不会改变游戏状态。
- 每个 intent 应该返回什么 message。
- 每个游戏有哪些状态字段。
- 游戏会主动发哪些 game_event。
- 哪些 intent 暂时不能支持，原因是什么。

第二类：动作、表情、灯效相关
- 哪些机械臂动作可以做。
- 哪些机械臂动作不能做，或者不适合儿童桌面场景。
- 哪些动作建议改成屏幕表情或灯效替代。
- 哪些星宝表情资源已经有。
- 哪些灯效可以实现。
- 是否建议新增、删除或改名某些动作/表情/灯效。

最重要的边界：

游戏不需要接大模型，也不需要理解孩子自由说话。游戏只处理固定 intent，并返回结构化结果。

星宝侧也不会直接给机械臂发送舵机角度、PWM、GPIO 或串口原始命令，只会输出类似 nod、smile、warm_breath 这样的高层名字。

第一阶段目标不是做很多功能，而是先跑通一个稳定闭环：
孩子说“我不会”
-> 星宝识别为 get_hint
-> 游戏返回当前提示
-> 星宝把提示用语音说给孩子听

你看完后，如果觉得某些字段、动作、表情不合理，可以直接在文档里改，或者单独返回一份修改建议。
